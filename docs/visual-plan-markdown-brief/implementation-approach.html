Verification

How we know it worked

Mechanical

  • pnpm runtime:check — generated runtime matches source.
  • pnpm test:server — validator coverage intact with the new fixture.
  • grep -rn "visual-plan/template.html" returns nothing outside history.

Behavioral

  • A plan authored from the brief publishes on the first push.
  • It contains six or more drawn figures, none of which is a labelled rectangle.
  • Two plans for different changes do not look like each other.

The third check is the real one. A single good plan proves nothing — the starter produced valid documents too. What this buys is variance in the right direction, and only a sample shows that.

Risks & assumptions

What could make this the wrong call

Removing the anchor raises variance in both directions

A weaker model given prose direction may produce something thinner than the form it replaced.

Mitigation: Part 4 of the brief enumerates the ten movements and Part 7 restates every hard constraint, so structural completeness stays specified. If the floor drops in practice, the answer is several small partial examples — one figure, one table — not a whole document the skill tells agents to copy.

The validator loses its only full-featured known-good input

An over-eager future tightening of validatePlanHtml would previously have been caught by plan-html.test.ts:73.

Mitigation: the replacement fixture must exercise inline <style>, inline SVG with <defs> and <marker>, <details>, tables, comments and data: URLs, or the coverage is not actually replaced.

Assumption: the shipped runtime is the static, no-JavaScript variant

The deployed skill and the copy at repository main have diverged. The deployed one says “Do not include JavaScript. Trace renders plans as static documents with scripting disabled.” The repository one permits sandboxed inline scripts and ships toolbars plus a 42-line script in its starter. This brief is written against the static variant.

If wrong: Part 7 of the brief and the closing paragraph of §3 need the interactive wording, and the brief should gain a short section on using interaction to reveal relationships rather than as decoration. A text edit to one file — but it must be settled before merge, because shipping the wrong half of the divergence is worse than either variant.

Why a worked example was rejected as the replacement

The obvious middle path is to keep a complete HTML document but call it “an example plan” rather than “the starter.” Rejected: it does not remove the anchor, it renames it. An agent with a complete, valid, on-disk document in front of it converges on that document's type scale and palette regardless of what the surrounding prose calls the file. The evidence is the existing skill, which already tells agents in plain language to treat the starter as a palette and not a form, and gets forms anyway.

Evidence: the measurements behind the “flat ceiling” claim
  • Type. body is 15px/1.65; h2 is 13px uppercase in --faint. No h1 rule exists. Seventeen of twenty-two font-size declarations fall between 10px and 13px.
  • Scale. Zero uses of clamp(). Canvas capped at max-width: 860px while carrying nine mandated content areas.
  • Color. #171717 / #1f1f1f / #262626 with a #3b82f6 accent, and no prefers-color-scheme block, so light-mode readers get the dark document.
  • Drawing. One <svg> in 791 lines — a 720×300 flowchart of four boxes and a diamond, generic enough to be about any change at all.
