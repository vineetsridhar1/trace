Use Playwright CLI for cloud browser control and video

Adopt Microsoft’s open-source Playwright CLI as the browser engine instead of building a Trace-specific automation protocol. Trace supplies the cloud-image packaging, invocation isolation, state-aware skill, lifecycle cleanup, and artifact upload; upstream supplies the persistent browser, snapshots, ref-based actions, debugging, and WebM recording.

Decision

Recommended: pin @playwright/cli in the provisioned runtime image and invoke playwright-cli directly from the bundled browser-video skill. Its named sessions preserve cookies and storage across commands; snapshots provide deterministic element refs; built-in console/request/screenshot commands provide inspection; built-in video-start, chapters, action annotations, run-code, and video-stop produce WebM.

This is precisely the upstream project’s intended use: its official README calls CLI + skills the best fit for coding agents because it avoids adapter-specific MCP registration and large tool schemas. Trace does not wrap every browser action or copy Playwright internals.

Upstream evidence reviewed on 2026-08-07
  • Microsoft playwright-cli README: CLI + skills is positioned as the best fit for coding agents; named sessions retain cookies/storage between calls; commands include snapshots, refs, screenshots, storage, console, requests, tracing, video, chapters, action annotations, and run-code.
  • Microsoft Playwright video guidance: a proof-of-work video should rehearse interactively, then run one “hero script” with deliberate pauses/annotations while recording.
  • Microsoft playwright-mcp: MCP is aimed at persistent, rich introspection but requires an MCP client configuration.
  • Chrome DevTools MCP: Apache-2.0 and capable, but officially supports Google Chrome/Chrome for Testing; usage statistics are on by default unless disabled.
  • Browserbase Stagehand: MIT and agent-oriented, but its own README says it is best with LLM-provider and Browserbase credentials.

End-to-end AI workflow

Exploration stays adaptive: after each Playwright command the CLI writes a snapshot containing URL/title and ref-addressable page state. The agent can request a fresh snapshot, screenshot, console messages, or requests, compare that with source and DB queries, update data or URL, reload, and continue in the same authenticated browser session.

Database, URL, auth, and video policy in the skill

Before browser work

  1. Read schema/migrations/services/seeds/API/router/auth code.
  2. Classify the DB hostname without printing DATABASE_URL.
  3. Prefer an app-owned seed/fixture/service/API; use narrow parameterized SQL only as fallback.
  4. For external DBs: no reset/drop/truncate/broad delete; namespace reversible demo rows.
  5. Query back required records and relationships; derive and curl the exact route.

Browser and proof

  1. Open the exact URL in the invocation’s named Playwright session.
  2. Use snapshot refs; inspect PNG for layout; inspect console/request summaries for failure.
  3. Establish auth through the supported UI/API and preserve cookies in the same session.
  4. Rehearse until DB/source/browser evidence agrees; generate stable locators.
  5. Reset to initial demo state, create the hero script, dry-run, reset again, then start video and execute it in one run-code command.
  6. Stop video, inspect metadata/playback, upload with $TRACE_CLI artifact push video, close, and clean namespaced external data.
Why a hero script: Playwright’s own video guidance recommends rehearsing interactively, then recording one scripted proof with deliberate pauses and annotations. The model does all open-ended reasoning before recording, so the final video has no minutes of dead air and does not require Trace to invent an action-clock encoder.

The bridge derives PLAYWRIGHT_CLI_SESSION and output paths from TRACE_INVOCATION_ID, never from agent-supplied names. A baked config selects /usr/bin/chromium, headless isolated profiles, a fixed viewport, bounded timeouts, workspace-restricted file access, and loopback origins. On completion/abort/replacement, the bridge closes that exact Playwright session and removes its temp output after the agent has uploaded the video.

Dependency policy: pin, build offline, and smoke the exact browser/video combination

Do not use @latest or npx -y at session time. The researched npm release is @playwright/cli@0.1.18 (Apache-2.0, Node ≥18, Playwright 1.63 alpha dated 2026-08-05); pin that exact resolved package after the implementation smoke confirms it. Use the existing system Chromium through upstream executablePath configuration, install the matching Playwright FFmpeg artifact during image build, and run open/snapshot/click/video/run-code/stop in CI without network access. Keep the upstream license in the installed npm package.

Implementation phases

Prove the upstream CLI in the Trace image

Pin Playwright CLI; configure system Chromium and isolated output; install its matching recording runtime; add an image smoke covering named sessions, snapshot refs, actions, console, screenshot, hero script, and WebM.

Exit criterion: no package or browser download occurs during an agent session

The smoke runs with network package access disabled and verifies playable WebM metadata. If the pinned CLI cannot reliably use the image’s Chromium, use the matching Playwright Chromium installed at image build rather than adding custom automation code.

Add invocation scoping and cleanup

Derive a unique Playwright session/config/output directory for each active invocation and close it from every bridge completion, abort, replacement, timeout, and shutdown path.

Isolation test: parallel cloud sessions retain separate tabs, cookies, storage, and output files

Test that one invocation cannot select another’s session via environment or CLI defaults, and that stale sessions are removed even when the coding tool exits unexpectedly.

Write and bundle the state-aware Trace skill

Teach database safety, state verification, exact-route/auth setup, Playwright exploration, ref-based action, visual/error inspection, hero-script generation, video recording, artifact upload, and cleanup.

The skill supplements upstream Playwright guidance rather than copying it

The Trace skill names product-specific invariants and tells the agent to consult playwright-cli --help and the installed upstream skill for command details. It never teaches a second command vocabulary.

Verify adaptive state repair and proof upload

A fixture app begins with wrong relational DB state, requires auth, and redirects to a parameterized route. The agent/test driver must discover, repair, inspect, rehearse, record, and upload; the unchanged Trace player must play the video.

Critical risks

Upstream maturity. Playwright CLI is young and currently tracks a fast-moving Playwright dependency. Pin an exact reviewed version, smoke the full command/video surface, and upgrade deliberately.
Database damage. Keep the prior guardrails: classify without logging secrets, prefer app-owned state setup, prohibit destructive external-DB operations, namespace and clean demo data.
Prompt injection from page content. Treat snapshots, console, and page text as untrusted application data, browse loopback previews only, and never interpret page text as instructions that override the skill or user request.
Secrets in scripts or video. Prepare auth before recording when possible, keep hero scripts in invocation temp output, do not print DB URLs/cookies/tokens, and review the WebM before upload.
Orphaned sessions. Explicit skill cleanup is insufficient alone; the bridge must close the invocation’s named Playwright session on every terminal path and runtime shutdown.
