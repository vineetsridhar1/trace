Gate browser video before Playwright ever acts

Adopt Microsoft’s open-source Playwright CLI for eligible web flows, but make the Trace skill abstain by default. A staged preflight decides whether the target is a controllable browser app, the environment and identities are authorized, deterministic data can be prepared safely, third-party dependencies are reachable in an approved sandbox, and the final recording can avoid secrets. Only then may the agent mutate state, authenticate, rehearse, record, and upload.

Decision

Recommended: make browser-video a gated proof workflow, not a universal post-coding step. For an eligible web flow, pin @playwright/cli in the provisioned runtime image and invoke it directly. For a native/mobile/CLI/backend target, unavailable third party, interactive MFA/CAPTCHA, unauthorized environment, unsafe data setup, or unreviewable sensitive output, the skill must not improvise—it selects an alternate proof or stops with a precise prerequisite.

This is precisely the upstream project’s intended use: its official README calls CLI + skills the best fit for coding agents because it avoids adapter-specific MCP registration and large tool schemas. Trace does not wrap every browser action or copy Playwright internals.

Mandatory eligibility gates

Fail closed: the agent evaluates these gates in order using read-only discovery first. A failed gate forbids later side effects. “The browser can click it” is never sufficient authority to access an account, change third-party state, expose customer data, or claim an integration works.

Allowed outcomes

real proof

All gates pass against the actual app-owned web flow and approved sandbox dependencies. Record and upload with a claim that matches what was observed.

limited proof

An existing accepted mock or sandbox substitutes for a dependency. Record only if useful, label the limitation in the artifact description/response, and never call it production end-to-end.

alternate proof

The feature is not browser-visible or video is unsafe/weak evidence. Run the appropriate unit, integration, API, CLI, log, trace, or platform-specific test instead; no fake browser demo.

blocked

Missing authority, credentials, human auth, safe state, or reachable services requires user/environment action. Stop before side effects and report the exact gate, evidence, and smallest prerequisite.

What is enforced where

Runtime guardrails · code-enforced

  • Invocation-owned browser session/profile/output paths.
  • Headless isolated Chromium with bounded timeouts.
  • Cleanup on completion, abort, replacement, timeout, and shutdown.
  • Recorder/tool availability and output validation before upload.
  • Existing Trace artifact authentication, media validation, and size policy.

Workflow gates · skill-enforced

  • Whether video fits the target and adds credible evidence.
  • Whether user authority covers the domain, identity, DB, and side effects.
  • Whether third-party access is real, sandboxed, mocked, or unavailable.
  • Whether data setup, auth, privacy, and claims are safe and truthful.
  • Which of the four dispositions the agent must report.
Explicit boundary: a skill governs a cooperative coding agent; it is not a security sandbox. V1 must not claim that prose prevents a compromised agent or page from bypassing network policy. Existing session permissions remain the security boundary. A future domain-egress enforcement layer is separate infrastructure work and is not required to ship the gated workflow.

Database, URL, auth, integration, and video policy

Before side effects

  1. Read target/runtime/schema/migrations/services/seeds/API/router/auth/integration code.
  2. Inventory every required origin, identity, credential, callback, provider, and human step.
  3. Classify DB hostname without printing DATABASE_URL; write the scoped setup/verification/cleanup plan.
  4. Choose real sandbox, accepted existing mock, alternate proof, or blocked—never silently replace a missing provider.
  5. Run gates 0–7 and state the disposition before login, mutation, or third-party action.

After eligibility passes

  1. Prepare app-owned state via seed/fixture/service/API; narrow parameterized SQL is last resort. External DBs forbid reset/drop/truncate/broad delete.
  2. Query back records and relationships; derive and curl the exact route.
  3. Open the exact URL, establish supported non-interactive auth, and preserve cookies in the same invocation session.
  4. Inspect snapshot, PNG, console, requests, source, and DB until the expected flow passes; do not cross an unapproved origin.
  5. Run gate 8, reset, dry-run the hero script, reset again, record, then run gate 9.
  6. Upload only a valid sanitized WebM, close the browser, remove temp data, and run planned namespaced cleanup.
Why a hero script: Playwright’s own video guidance recommends rehearsing interactively, then recording one scripted proof with deliberate pauses and annotations. The model does all open-ended reasoning before recording, so the final video has no minutes of dead air and does not require Trace to invent an action-clock encoder.
Third-party examples: prove only the boundary actually under control
  • Allowed real proof: an authorized Stripe/Slack/etc. test tenant is already configured, credentials are available through approved mechanisms, no human challenge is required, and the requested side effects are scoped and reversible.
  • Allowed limited proof: the repository already uses a mock OAuth/provider server and the task accepts it. The response and artifact label say the provider was mocked.
  • App-boundary proof only: show that the app emits the expected request or handles a provider error, but do not claim the external system received or processed it.
  • Blocked: missing invitation/API key, production-only account, MFA/CAPTCHA/consent prompt, inaccessible email/SMS callback, paid transaction, customer tenant, or provider outage.

The bridge derives PLAYWRIGHT_CLI_SESSION and output paths from TRACE_INVOCATION_ID, never from agent-supplied names. A baked config selects /usr/bin/chromium, headless isolated profiles, a fixed viewport, bounded timeouts, and workspace-restricted file access. The skill defaults to the app’s loopback preview origins; an external origin is eligible only when the user’s task scope and an approved sandbox configuration identify it. On completion/abort/replacement, the bridge closes that exact Playwright session and removes its temp output after upload or abstention.

Dependency policy: pin, build offline, and smoke the exact browser/video combination

Do not use @latest or npx -y at session time. The researched npm release is @playwright/cli@0.1.18 (Apache-2.0, Node ≥18, Playwright 1.63 alpha dated 2026-08-05); pin that exact resolved package after the implementation smoke confirms it. Use the existing system Chromium through upstream executablePath configuration, install the matching Playwright FFmpeg artifact during image build, and run open/snapshot/click/video/run-code/stop in CI without network access. Keep the upstream license in the installed npm package.

Implementation phases

Prove the upstream CLI in the Trace image

Pin Playwright CLI; configure system Chromium and isolated output; install its matching recording runtime; add an image smoke covering named sessions, snapshot refs, actions, console, screenshot, hero script, and WebM.

Exit criterion: no package or browser download occurs during an agent session

The smoke runs with network package access disabled and verifies playable WebM metadata. If the pinned CLI cannot reliably use the image’s Chromium, use the matching Playwright Chromium installed at image build rather than adding custom automation code.

Add invocation scoping and cleanup

Derive a unique Playwright session/config/output directory for each active invocation and close it from every bridge completion, abort, replacement, timeout, and shutdown path.

Isolation test: parallel cloud sessions retain separate tabs, cookies, storage, and output files

Test that one invocation cannot select another’s session via environment or CLI defaults, and that stale sessions are removed even when the coding tool exits unexpectedly.

Write and bundle the gate-first Trace skill

Encode the ordered gates and four dispositions first; only the passing path teaches database safety, state verification, exact-route/auth setup, Playwright exploration, ref-based action, visual/error inspection, hero-script generation, video recording, artifact upload, and cleanup.

The skill supplements upstream Playwright guidance rather than copying it

The Trace skill names product-specific invariants and tells the agent to consult playwright-cli --help and the installed upstream skill for command details. It never teaches a second command vocabulary. It includes a concise decision-report template: disposition, failed/limited gate, observed evidence, side effects already taken (normally none), and smallest next prerequisite.

Verify positive, limited, alternate, and blocked paths

The positive fixture begins with wrong relational DB state, requires auth, and redirects to a parameterized route; it must be repaired, rehearsed, recorded, uploaded, and played. Negative fixtures cover native/API-only targets, unavailable third parties, existing mocks, MFA, external DB danger, sensitive viewport data, unstable rehearsal, and invalid recordings; each must select the expected disposition without prohibited side effects.

Critical risks

Upstream maturity. Playwright CLI is young and currently tracks a fast-moving Playwright dependency. Pin an exact reviewed version, smoke the full command/video surface, and upgrade deliberately.
Database damage. Keep the prior guardrails: classify without logging secrets, prefer app-owned state setup, prohibit destructive external-DB operations, namespace and clean demo data.
False proof. A browser video proves only what appears and is asserted in that run. Label mocks/sandboxes, do not infer backend or provider success from UI appearance, and choose alternate evidence for non-browser behavior.
Uncontrolled third parties. Missing credentials, provider outages, MFA/CAPTCHA, consent screens, and production tenants are expected abstention cases—not automation bugs to route around.
Prompt injection from page content. Treat snapshots, console, and page text as untrusted application data, browse only the approved app/sandbox origins, and never interpret page text as instructions that override the skill or user request.
Secrets in scripts or video. Prepare auth before recording when possible, keep hero scripts in invocation temp output, do not print DB URLs/cookies/tokens, and review the WebM before upload.
Orphaned sessions. Explicit skill cleanup is insufficient alone; the bridge must close the invocation’s named Playwright session on every terminal path and runtime shutdown.
