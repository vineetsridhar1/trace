Durable publishing for session-built apps

Approve a durable deployment lifecycle that snapshots a managed app session, hands that snapshot to an external build worker, and keeps publishing status available after the cloud coding session sleeps.

Decision publish checkpoints, never a live workspace Boundary Trace records intent; a worker builds and hosts Gate worker, queue, bucket, role, and callback URL must exist

What needs approval

Make deployment state independent of the cloud session. The proposed AppDeployment record is the durable source for the selected Git checkpoint, lifecycle status, public URL, and failure reason. Session processes remain ephemeral; a publish request creates a separate asynchronous deployment.

Implementation moves

Persist one deployment lifecycle per publish request

AppDeploymentService.publish() locks by session group, requires a managed app and its latest GitCheckpoint, deduplicates an active request for the same checkpoint, and supersedes older in-flight requests. This prevents a retry from creating two deployments for identical source.

Proof: service tests cover no checkpoint, same-checkpoint reuse, superseding an in-flight publish, and dispatch failure.

Make transitions authenticated and monotonic

updateFromCallback() stores only a hash of a fresh token, accepts queued → building → deploying → live or failure, ignores duplicate/terminal callbacks, and supersedes an earlier live deployment only when a successor is live.

Proof: verify bearer-token rejection, invalid transition rejection, duplicate delivery, and a failed replacement preserving the currently live deployment.

Dispatch an immutable source bundle instead of session files

AwsAppDeploymentDispatcher archives the selected commit from managed Git, streams a size-limited tarball to S3, then sends a versioned AppDeploymentJob to SQS using assumed-role credentials. The source key is deployment-specific.

Proof: dispatcher tests confirm streaming behavior and reject archives over 100 MB; add an integration exercise against a disposable queue and bucket.

Expose lifecycle state through existing product channels

The GraphQL query/mutation, generated types, event handlers, Zustand table, and AppDeploymentCard make publish progress, errors, and a live URL visible in the Applications panel. UI actions remain fire-and-forget; events reconcile state.

Proof: handler tests upsert queued/updated events and a browser test confirms the panel reaches live after callback-driven events.

Decisions that reduce failure impact

Checkpoint, not workspace

Session shutdown or later edits cannot alter an in-progress deployment. A commit SHA is visible on the deployment and can be replayed.

At most one current deployment

An advisory lock serializes publishes per session group. A newer request marks earlier active work superseded.

Only a live successor replaces live state

Publishing failures are durable and visible but must not remove a prior public URL.

Callback tokens are stored hashed

The worker receives the secret once. Trace verifies it in constant time and never exposes it through GraphQL or events.

Release gate and unresolved boundary

This branch implements Trace-side orchestration, not the worker or cloud infrastructure. It will fail closed with “Published app deployments are not configured for this environment” until AWS_REGION, role ARN, source bucket, queue URL, and a valid public callback URL are supplied. The queue consumer must honor AppDeploymentJob version 1 and issue the authenticated callback progression.
Evidence and review focus
  • apps/server/src/services/app-deployment.ts owns authorization, idempotency, state transitions, and events.
  • apps/server/src/services/app-deployment-dispatcher.ts owns Git archive streaming, S3 upload, role assumption, and SQS submission.
  • apps/server/src/routes/app-deployment-callback.ts limits the callback surface to known statuses and bearer authentication.
  • apps/web/src/components/session/applications/AppDeploymentCard.tsx renders the latest durable deployment rather than a running process.
