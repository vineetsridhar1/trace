Secure credentials for ephemeral cloud runtimes

Remove raw user and organization credentials from ECS RunTask overrides. A short-lived runtime bootstrap grant establishes a session-bound control channel; provider credentials remain server-side and are used only by scoped Git and model egress brokers.

11 code areas5 delivery phasesSecurity-sensitiveMigration required

Outcome and scope

In scope

  • Eliminate plaintext provider credentials from the provisioned-runtime launcher payload and ECS task overrides.
  • Issue a single-use, runtime-generation-bound bootstrap grant and exchange it for scoped runtime capabilities.
  • Use managed Git and server-side provider egress paths so user API keys and Codex session material never enter the task.
  • Add audit-safe telemetry, revocation, tests, rollout controls, and credential-rotation runbook.

Explicitly deferred

  • A generic “fetch any org secret” API for containers; it would recreate the exfiltration boundary.
  • Granting the ECS task role broad Secrets Manager or database access.
  • Changing local/Electron runtime credential behavior in this first cut.
  • Supporting ChatGPT-session auth in cloud until its server-side execution/proxy contract is proven.

Current state and security boundary

apps/server/src/lib/runtime-adapters.ts decrypts org runtime secrets through resolveProvisionedRuntimeEnv and user tokens through resolveUserApiTokenEnv, then sends all of them in bootstrapEnv to the provisioned launcher. The launcher maps that object to ECS environment overrides, which are returned by task inspection APIs.

apps/server/src/services/api-token.ts, codex-credential.ts, and org-secret.ts correctly encrypt data at rest, but decryption immediately crosses into an ephemeral task. apps/container-bridge/src/tool-auth.ts additionally writes Codex session JSON to disk. managed-git.ts already offers a session-bound managed Git token, so Git can move to that capability rather than a user GITHUB_TOKEN.

Boundary to enforce: a compromised runtime may use only the capabilities needed for its assigned session. It must never be able to read, list, refresh, or reuse the owner’s raw API keys, OAuth/ChatGPT-session credentials, SSH keys, or unrelated organization secrets.

Decisions

Chosen: brokered capability delivery

Use the existing Trace control plane, encrypted-at-rest secret services, managed-Git authorization pattern, Redis, and runtime ownership checks. ECS receives a disposable bootstrap grant only.

Rejected: ECS secret injection as the main solution

Secrets Manager references would hide values from task-definition output, but values still become process environment and dynamic per-user secrets cannot safely be selected via task overrides. It does not protect against code running in the task.

Provider policy: Anthropic and OpenAI API-key traffic will be proxied. Git will use Trace-managed, repository- and runtime-scoped credentials. Codex API-key traffic follows the OpenAI egress path. ChatGPT-session and access-token modes will be blocked for cloud runtime launch until a server-side Codex execution adapter is available; they remain valid for local runtimes.

Implementation phases

Containment and contract inventory

Rotate credentials exposed through the prior task inspection; disable task-definition override logging/debug output that serializes environment values. Catalog every current bootstrapEnv name by class: runtime identity, non-secret configuration, managed Git, provider API key, OAuth/session credential, and arbitrary org secret. Define an allowlist of non-secret ECS bootstrap fields and reject all credential-shaped keys at the launcher boundary.

Runtime bootstrap grant and broker

Add a dedicated credential capability module with signed grant creation/verification, a distinct audience and 10-minute maximum TTL, Redis-backed single-use consumption, and an explicit revoke-by-runtime/session key. Add a runtime route that authenticates the grant, verifies the persisted connection’s runtimeInstanceId and session ownership, and returns only provider-independent capability metadata and short-lived scoped bearer tokens. Refactor inline runtime routes from index.ts into the same route module so auth logic is centralized.

Brokered provider and Git access

Create a server-side egress service/routes for the minimum Anthropic and OpenAI-compatible request surface used by the cloud tools. The service resolves the owner credential only after capability authorization, applies model/provider/session allowlists and request-size/rate controls, forwards over HTTPS, and redacts failures. Change managed Git setup to mint runtime-scoped managed-Git credentials only; remove GITHUB_TOKEN and SSH_PRIVATE_KEY from cloud bootstrap. Keep provider credentials out of bridge process environment; supply the tool only with local proxy URL plus an ephemeral egress token.

Bridge/tool integration and safe migration

At bridge boot, exchange the grant once and retain only the resulting expiring capabilities in memory. Update Claude/Codex tool setup to point at the brokered endpoint and use token refresh that requires the long-lived runtime control identity plus an active lease. Remove CODEX_AUTH_JSON file installation and cloud credential-sync behavior. Gate the new path behind a cloud-runtime credential mode flag; default new sessions to broker mode after integration tests pass, retain the legacy path only for a short rollback window, then delete it.

Deploy and prove the boundary

Deploy the control plane before the runtime image, use a canary organization/session, and inspect the resulting ECS task through the same CLI path that exposed the issue. Confirm task overrides contain no raw provider, Git, SSH, or Codex credentials; validate normal Claude/Codex API-key runs, managed repository clone/push, revocation on stop/move, restart behavior, expiry, replay, cross-session misuse, and denied ChatGPT-session cloud launch.

Risks and mitigations

RiskMitigation
Bootstrap grant is replayed from an ECS inspection or log.Ten-minute audience-bound JWT plus Redis SET NX consumption, exact persisted runtime-generation check, lease check on refresh, and immediate revocation on stop/move.
Proxy becomes a general credential oracle.No “get secret” operation. Each endpoint has fixed provider semantics, validates session/runtime/user ownership, and emits only redacted audit metadata.
Tool lacks required base-URL/auth-header support.Validate Claude Code and Codex configuration in a disposable runtime before enabling each provider; retain a feature flag and fail closed rather than falling back to raw keys.
Provider streaming or large requests overload the API service.Stream responses without buffering, bound headers/body sizes, apply per-runtime limits, and place the egress proxy behind the existing production ingress/load-balancing policy.
Existing credentials have already been exposed.Rotate affected GitHub, Anthropic, OpenAI, and Codex credentials before rollout; invalidate current cloud runtimes and record completion in the operational runbook.
