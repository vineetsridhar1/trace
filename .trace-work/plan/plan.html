Keep personal keys out of cloud containers

Today, Trace gives a new cloud container copies of the user’s real API and login keys. The safer design is for Trace to keep those keys and give the container a temporary pass that works only for one session.

4 stages No database migration expected Security improvement Approval required before coding

The idea in everyday language

Think of a hotel key card. A hotel does not hand every guest the master key. It gives each guest a card that opens one room for a limited time. Trace should do the same: keep the master credentials safe and give each cloud container a temporary pass for one session.

What is wrong today

Today

  • Trace decrypts the user’s real Anthropic, OpenAI, GitHub, SSH, or Codex credentials.
  • Those credentials are copied into the cloud container when it starts.
  • A person or system with permission to inspect the AWS task can see them.
  • Code running inside the container can also read them.

After this change

  • Trace keeps the real credentials on the server.
  • The container receives only a short-lived temporary pass.
  • The pass works for one user, one session, and one container.
  • Stopping or moving the session cancels the pass.

How it will work

1. Trace starts a sessionCreates a temporary one-use pass
→
2. Container checks inUses the pass to prove which session it belongs to
→
3. Trace acts as middlemanUses the real credential without revealing it
→
4. Work completesGit or AI response returns to the container

The container can ask Trace to perform an approved action, such as sending a prompt to Anthropic or pushing to the session’s repository. It cannot ask Trace to show, download, or refresh the real credential.

Implementation stages

Build the temporary-pass system

Create passes that expire after a few minutes, work only once during startup, and are tied to the exact user, session, and container. Trace checks that the session is still active before accepting one.

Connect Git and AI tools through Trace

Reuse Trace’s existing session-specific Git access. Add a controlled middleman for Anthropic and OpenAI requests. It will limit which provider, model, and session each temporary pass can use.

Remove real credentials from container startup

Update the container so it checks in with its temporary pass. Remove API keys, GitHub tokens, SSH keys, and Codex login files from the information sent to AWS.

Roll out carefully

Enable the new system for a small test group first. Confirm normal model requests, Git operations, restarts, and shutdowns. Then make it the default and delete the old credential-copying path.

What is included and excluded

Included

  • Temporary session passes.
  • Safe Git and AI request handling.
  • Canceling access when a session stops or moves.
  • Tests, monitoring, credential rotation, and a gradual rollout.

Not in the first version

  • A way for containers to download arbitrary secrets.
  • Changes to local desktop sessions.
  • Cloud use of a personal ChatGPT login until the safe approach is confirmed.
  • Unrelated AWS or session-lifecycle changes.

Main risks

RiskHow we reduce it
Someone steals the temporary pass.It expires quickly, works only for one session/container, and is canceled when that session ends.
The middleman is used for unapproved requests.It checks the user, session, provider, model, request size, and rate every time. It never has a “show me the key” operation.
Claude Code or Codex cannot use the middleman.Test each tool in a disposable cloud session before enabling it. If it is incompatible, that tool stays on the old path only during the limited rollout period; production fails safely before the old path is removed.
Previously exposed keys remain valid.Rotate the affected Anthropic, OpenAI, GitHub, and Codex credentials before rollout.

How we will know it is finished

CheckExpected result
Start a fresh cloud sessionThe selected AI tool completes a real request.
Clone and push codeThe session can use its repository without receiving the user’s GitHub or SSH credential.
Restart the containerThe replacement receives a new temporary pass and resumes normally.
Stop or move the sessionThe previous container immediately loses access.
Try an expired, copied, or wrong-session passTrace refuses it.
Inspect the AWS taskNo Anthropic, OpenAI, GitHub, SSH, or Codex credential appears in the task details.
Run the repository test and build commandsAll focused tests and the full build pass.

Technical appendix

The main server changes are in apps/server/src/lib/runtime-adapters.ts, a new runtime-credential service and route, apps/server/src/index.ts, and apps/server/src/services/managed-git.ts. The cloud-container changes are in apps/container-bridge/src/index.ts, tool-auth.ts, and bridge.ts. Focused tests will cover temporary-pass security, secret-free startup data, Git, AI requests, restart, and revocation.

The production AWS setup lives outside the code paths inspected here. Before implementation changes AWS permissions, we must identify the repository or stack that owns the ECS task and its roles.
