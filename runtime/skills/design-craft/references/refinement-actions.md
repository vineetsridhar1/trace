# Refinement actions

Use the narrowest action matching the request. Preserve the brief, current visual world, content, behavior, and out-of-scope screens unless the user explicitly asks for redesign.

| Intent | Change | Protect |
| --- | --- | --- |
| Critique | Identify specificity, hierarchy, cognitive-load, interaction, and craft problems; do not edit unless asked. | Independent judgment before detector findings. |
| Polish | Repair defects and system drift across the whole path. | Existing concept and identity. |
| Bolder | Strengthen one structural, typographic, color, imagery, or interaction thesis. | Scope and usability; adding effects alone is not bold. |
| Quieter | Reduce competing emphasis, saturation, decoration, or motion. | The direction's character and primary focal point. |
| Distill | Remove duplicate choices, unnecessary containers, redundant copy, and avoidable steps. | Required information, recovery, and expert capability. |
| Colorize | Choose semantic roles and apply color at system scale. | Brand colors, status meaning, and contrast. |
| Typeset | Fix role scale, measure, wrapping, weight, rhythm, and numeric treatment. | Content hierarchy and localization range. |
| Layout | Fix topology, grouping, alignment, density, and responsive composition. | Task order and platform expectations. |
| Animate | Add motion that explains cause, state, or hierarchy. | Reduced-motion behavior, focus, and performance. |
| Delight | Add one useful, humane, product-specific moment. | Task speed and emotional appropriateness. |
| Clarify | Rewrite actions, labels, errors, permissions, empty states, and help by function. | Factual meaning, terminology, and brand voice. |
| Adapt | Recompose navigation, hierarchy, content priority, and controls for the target viewport. | Product capability; adaptation is not scaling. |

When the user asks for live comparison in a Design session, preserve the original and add two or three labeled variation artboards beside it. Keep viewport, state, content, and product facts constant so the comparison isolates the design decision. In an App session, prefer one coherent implementation unless the user explicitly asks for a comparison view. Once the user chooses, retain the selected direction and remove only the temporary alternatives.

Before finishing any refinement, inspect the complete affected path at representative widths. A focused request should not leave adjacent states or breakpoints below the same quality bar.
